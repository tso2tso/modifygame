## 1. 游戏概述

### 1.1 故事背景

1904年，波斯尼亚。科瓦奇家族在巴尔干山区发现了一座金矿，从此开启了一段横跨两次世界大战、五个时代的半世纪家族传奇。玩家扮演家族的掌舵者，在帝国末日、战争硝烟、工业革命、政治风暴和战后重建中经营矿业、壮大家族、角逐区域霸权。

### 1.2 游戏时间线

| 章节 | 时代名称 | 年份 | 关键词 | 战争章节 |
|------|---------|------|--------|---------|
| 第一章 | 铜版帝国 | 1904-1913 | 矿业起步、帝国控制 | 否 |
| 第二章 | 战报红章 | 1914-1918 | 第一次世界大战 | **是** |
| 第三章 | 黑金工业 | 1919-1940 | 战后重建、大萧条 | 否 |
| 第四章 | 战时灰幕 | 1941-1945 | 第二次世界大战 | **是** |
| 第五章 | 战后余烬 | 1946-1955 | 社会主义改造、冷战博弈 | 否 |

- **起始**: 1904年 第1季度
- **终止**: 1955年 第4季度
- **总计**: 约 208 个季度 (52年 × 4季度)

### 1.3 核心玩法

- **矿业经营**: 开采金铜煤，升级矿山，管理工人
- **金融投资**: 7只股票的 Fair Value Anchored GBM 模拟，贷款杠杆
- **科技研发**: 56项科技的分叉互斥树（含扩展科技）
- **家族管理**: 6个岗位、5维属性匹配，最多11名成员
- **区域争霸**: 3个地区的控制度与AI角力
- **装备与小队**: 6级装备体系、工厂生产、老兵系统
- **历史事件**: 43个固定事件 + 35个随机模板 + 5个分支事件，真实历史节点抉择
- **大国博弈**: 15个大国的军事/经济/战争疲劳模拟，征服与继承
- **欧洲地图**: 17个国家的主权变迁、抵抗运动与解放
- **外国矿产**: 侦察、开采并重建被占领国矿山，获取海外资源
- **武力掠夺**: 劫掠商队、夺取矿脉、勒索外资，声誉系统平衡收益与代价
- **三种胜利**: 经济胜利、军事胜利、支配胜利（相对胜利制）

## 2. 核心循环与回合结构

### 2.1 回合 = 1个季度

每个回合代表一个季度（春/夏/秋/冬），流程如下：

```
回合开始
  │
  ├─ 阶段0: 通胀推进（影响本季价格）
  ├─ 阶段1: 经济结算（采矿→出售→收入→支出→税收）
  ├─ 阶段1.5: 股市 GBM 更新
  ├─ 阶段1.6: 贷款利息结算 & 到期还本 & 破产检测
  ├─ 阶段1.7: 科技研发推进
  ├─ 阶段1.8: 装备生产推进（工厂/外包队列）
  ├─ 阶段2: 事件检查（固定 + 随机同季可并发）
  ├─ 阶段3: 胜利点结算（经济 / 军事 / 支配）
  ├─ 阶段4: 修正器推进（到期移除）
  ├─ 阶段4.5: 影响力自然衰减（-1/季，文化行动豁免）
  ├─ 阶段4.6: 掠夺结算（冷却tick/声誉恢复/矿脉产出/公敌控制衰减）
  ├─ 阶段4.65: 监管压力推进
  ├─ 阶段4.7: 特殊内容检查
  ├─ 阶段5: 武装士气衰减（-2/季，军务主管可减缓）
  ├─ 阶段6: AI 势力更新（增长/扩张/态度变化/主动消费/崩溃检测）
  ├─ 阶段6.2: 外资控制度持续性修正器（基于全局外资存在度）
  ├─ 阶段6.5: AI 可能主动进攻 + 击败检测
  ├─ 阶段6.7: 大国博弈（激活/漂移/派系/继承/征服/抵抗/代理AI）
  ├─ 阶段6.8: 历史分支事件检查（5个关键分支决策点）
  ├─ 阶段6.9: 动态治安等级调整（RecalcSecurity，军事力量 vs AI威胁）
  ├─ 阶段7: 工人士气（工资满足度）
  ├─ 阶段8: 家族培养进度
  ├─ 阶段8.5/8.55/8.56: 探矿推进（金矿/铜矿/煤矿分别倒计时）
  ├─ 阶段8.6: 外国矿产推进（侦察倒计时 + 主权校验清理）
  └─ 阶段9: 推进季度 → 刷新 AP
```

### 2.2 玩家行动阶段

在结算完成后，玩家进入行动阶段（phase = "action"），可自由分配行动点执行操作，直到点击"结束回合"。

## 5. 经济系统

### 5.1 收入来源

1. **黄金出售**: 手动或自动出售，价格 = 基础价(50) × 通胀^1.2（超线性） × 科技加成 × 事件修正 × 战时溢价(+30%)
2. **铜出售**: 每季可自动全量出售，价格 = 基础价(8) × 通胀 × 事件修正
3. **煤炭采集与出售**: 工业区有煤炭储量时，每季自动采集（基础15单位）并出售（扣除工厂煤耗、工业运营煤耗和矿山分配后）。**采煤受矿山等级和控制度影响**，产量 = 基础 × 矿山等级乘数 × 开发度加成 × max(0.30, 控制度/100)。矿山等级乘数取所有活跃矿山的最高等级，每级+20%。
4. **地区被动收入**:
   - 矿区控制度 ≥50%: 每超10% → +20 × 通胀
   - 工业区控制度 ≥40%: 控制度 × 1.5 × 通胀 × max(0.4, 1+民需修正)（此为**贸易收入**，与煤炭采集独立）
   > ⚠️ 注意：煤炭采集收入和工业区贸易收入是两个独立来源。玩家初始工业区控制度20%，低于40%贸易门槛，但仍可获得煤炭采集收入。
5. **金融网络被动收入**: 科技 `b5_finance_net` 解锁，80/季
6. **贸易被动收入**: 科技 `b4a_trade_route` / `b4b_smuggling` 等
7. **暗影收入**: 事件/修正器带来的灰色收入（受通胀缩放）
8. **外国矿产收入**: 开采被占领国矿山获得的金/铜/煤收入（详见§34）
9. **黄金储备利息**: 持有黄金超过20单位的部分，每季按0.5%利率折算现金收益

### 5.2 支出项目

1. **工人工资**: 工人数 × 基础工资(8) × 劳动力成本因子 × 雇佣成本乘数
   - 雇佣成本乘数 = max(0.5, 1.0 + 科技折扣)，最低降至50%
   - **解雇补偿**: 每解雇一名工人需支付 5 克朗遣散费
2. **军事开支**: 护卫数 × 护卫工资(12) × 对冲通胀 + 装备维护费 + 工厂维护费
   - 对冲通胀 = 通胀 × (1 - 黄金对冲百分比)，黄金储备可减免军事支出中的通胀部分
3. **补给开支**: 护卫数 × max(1, 人均补给 - 科技减免) × 补给单价(2) × 对冲通胀 × 财务折扣 × (1 + min(0.5, 运输风险))
4. **税收（财富税）**: 当前持有现金 × 税率(基础3%)
   > ⚠️ 注意：这是对**现金存量**征税，而非对当季收入征税。持有现金越多税额越高，形成主动花钱的逆向激励。
5. **AI 惩罚**: AI 存在度超50%的地区，每超10% → +15 × 通胀
6. **运输风险损失**: 暴露收入（金/铜/地区/暗线）× min(0.30, 运输风险 × 0.25)
7. **装备维护费**: 小队装备维护成本（详见§21）

### 5.2.1 收入修正器

总收入受 `income_mod` 修正器影响，范围 **-0.75 ~ +1.00**（钳位）：
- 正值: 收入增加（如贸易利好）
- 负值: 收入减少（如制裁），但负向修正不超过本季度总收入，防止现金被推入深度负值

### 5.2.2 预估模式

经济系统提供 `GetEstimate()` 预估接口，用于 UI 显示下季收支预测。内部使用 `_estimate_mode` 标记进入只读模式，防止预估计算产生副作用（如修改矿山 `initial_reserve`）。

### 5.3 税率计算

```
有效税率 = 基础税率(3%)
  + 事件修正
  - 合法性 × 0.0004
  - 政治地位 × 0.0004
  - 民众支持 × 0.0002
  + 腐败风险 × 0.0005
  + max(0, 风险) × 0.0004
  + 监管压力 × 0.0008
  - 首都控制度减税 (≥30%: 每超10% 减1%)
  × (1 - 内政总监加成 × 0.2)     ← 满配时减20%税率
  
范围: 0% ~ 35%（钳位后取整）
战时基础税率: 12%
```

> **内政总监减税**: 税率计算最后一步乘以 `(1 - civilBonus × 0.2)`。满配（bonus=1.0）时税率降低20%，半配降低10%。

### 6.1 矿山参数

| 参数 | 值 |
|------|-----|
| 基础金矿产出 | 2 单位/季 |
| 基础铜矿产出 | 5 单位/季 |
| 基础煤炭产出 | 15 单位/季（受矿山最高等级加成） |
| 等级产出加成 | +20%/级（金/铜/煤均受益） |
| 升级费用 | 300 × 等级 × 资产价格因子 |
| 最大等级 | 5 |
| 事故基础概率 | 5% |
| **季度开采上限** | **初始储量 × 8%** |

> ⚠️ `max_quarterly_depletion_ratio = 0.08`：单矿每季度最多开采其初始储量的8%。例如初始储量500的矿山，每季最多产出40单位。该机制防止高等级矿山在短短几季内耗尽储量。

### 6.2 矿山产出公式

```
raw = (基础 + 事件修正 + 基础产出加成 + 矿山个体加成) 
      × 等级乘数 × (1 + 岗位加成 × 0.5) + 工人加成
raw = raw × (1 + 科技乘法加成)
raw = raw × (1 + 煤炭电力加成)
产出 = min(floor(raw), 矿山储量, 季度开采上限)

其中:
- 等级乘数 = 1.0 + (等级-1) × 0.20
- 工人加成 = floor(本矿分配工人数 / 10 × 工人效率乘数)
  - 本矿分配工人数 = 总雇佣工人数 / 活跃矿山数（均分）
- 岗位加成 = 矿业总监的属性匹配度 × 0.5（满配+50%，半配+25%）
- 季度开采上限 = max(1, floor(初始储量 × 0.08))
- 煤炭电力加成 = 玩家分配煤炭后的 mine_coal_power_bonus（上限30%）
```

## 7. 股票市场 (Fair Value Anchored GBM)

### 7.1 模型说明

使用**公允价值锚定的几何布朗运动 (Fair Value Anchored GBM)** 模拟股价。在标准 GBM 基础上，增加了公允价值（base_value）、通胀挂钩（inflation_alpha）和均值回归（theta）机制：

```
-- 公允价值随通胀动态调整
fair_value = base_value × (1 + inflation_alpha × (当前通胀 - 1))

-- 均值回归漂移
mean_revert = theta × ln(fair_value / 当前价格)

-- GBM 价格更新
effective_mu = mu + mean_revert
P_{t+1} = P_t × exp((effective_mu - sigma²/2) × dt + sigma × eps × sqrt(dt))
其中 eps ~ N(0,1), dt = 1季度
```

**设计意图**: 标准 GBM 中股价可无限漂移至极端值；锚定公允价值后，股价在远离基本面时会被拉回，产生更真实的"泡沫-崩盘"周期。

### 7.2 七只股票

| imperial_railway | 帝国铁路公司 | 8.30 | -0.003 | 0.07 | 8.30 | 0.90 | 0.15 | transport |
| balkan_shipping | 巴尔干行船 | 15.60 | 0.000 | 0.12 | 15.60 | 0.95 | 0.12 | transport |

### 7.3 三层修正

1. **L1 基本面**: 每只股票自带的 mu / sigma + 公允价值均值回归
2. **L2 事件修正**: `event_mu_mods` 数组，临时叠加 delta_mu
3. **L3 全局修正**: 战争章节 sigma × 1.8 (战时波动放大)

### 7.4 价格保护

| 绝对上限 | 99999.0 | `ABS_PRICE_CEIL` |
| 软上限 | fairValue × 5.0 | `SOFT_CEIL_MULT`，基于公允价值 |
| 软下限 | fairValue × 0.15 | `SOFT_FLOOR_MULT`，基于公允价值 |
| 历史保留 | 12 季度 | 用于 UI 走势图 |

### 7.5 公允价值计算

```
fairValue = base_value × inflation^alpha × (1 + sectorBonus)
```

其中 `sectorBonus` 根据玩家经营状态动态计算（-1 ~ +1）：

| 板块 | 关键影响因素 |
|------|-------------|
| mining | 活跃矿山数 × 0.03（上限 0.5） |
| military | 战时 +0.8，和平 -0.2 |
| transport(铁路) | 铁路封锁利空 -0.3，工业控制度利好 |
| transport(航运) | 战时 -0.3，和平 +0.1 |
| finance | 金融危机 -0.3，杠杆过高惩罚 |
| trade | 贸易收入利好，封锁利空 |

### 7.7 运营漂移 (Operational Drift)

每季度经济结算后，根据玩家实体经营状况向相关股票注入小幅基本面修正（±3.5% 区间，持续1季），走 `event_mu_mods` 管线。影响因素包括：

- **矿业股**: 矿山数量、等级、矿区控制度
- **军工股**: 兵工厂等级、生产队列、战时加成
- **铁路股**: 工业控制度、铁路封锁状态
- **金融股**: 杠杆率、监管压力、金融被动收入
- **贸易股**: 贸易被动收入、铁路通畅度

### 7.8 买卖机制

- 即时成交，按当前价格计算
- 持仓追踪均价成本
- 卖出即到账
- **收益加成**: 科技 `stock_boost_all` 转化为 `stock_return_bonus`，对卖出正利润部分加成

### 7.9 做空机制

需研究 `b7_short_selling` 科技解锁。保证金 50%，每季利息 5%，最大持仓 8 季，亏损 >= 保证金×80% 强制平仓。利息折扣来自奥匈银行信托持股（influence→4%, control→3%）。

### 7.10 庄家操盘

需持有巴尔干新闻社 + 解锁对应文化科技。三种操盘行动：
- **做多操盘**（Pump）：注入正 delta_mu，基础成功率 70%
- **做空操盘**（Dump）：注入负 delta_mu，基础成功率 60%
- **联合操盘**：同时做多一只+做空另一只，基础成功率 50%

### 7.11 操盘反制机制（M1~M4）

四个机制从机制层面约束操盘滥用：

| 机制 | 说明 |
|------|------|
| M1 媒体公信力 | 消耗性资源（初始 60/100），操盘消耗公信力，越低成功率越低 |
| M2 方向互斥 | Pump/Dump 成功后 3 季不能反向操盘同一股票（不限普通买卖） |
| M3 解耦新闻社 | 做空利息折扣从新闻社移至银行信托，打破自耦合 |
| M4 AI 对手盘 | 外资概率反制（Pump 30% / Dump 25% / 联合 45%），注入反向 delta_mu |

> 详见 `docs/media-stock-and-shorting-plan.md` 第七节。

| 大额 | 资产×60% | 2000 | 6% | 8 |

- **最大同时贷款数**: 3
- **最大杠杆率**: 80%
- **动态利率**: 实际利率 = 基础利率 × (1 + 当前杠杆 × 1.5)

### 8.2 违约处理（渐进式）

```
利息到期
  │
  ├─ 现金充足 → 正常付息
  │
  └─ 现金不足 → 强制清算流程:
       ├─ 1. 变卖黄金
       ├─ 2. 降级矿山（回收50%价值）
       ├─ 3. 士气惩罚 -5
       │
       ├─ 清算后凑够 → 正常扣款
       └─ 清算后仍不足 → 真正违约
            └─ 本金膨胀 +15%
```

### 8.3 展期

- 到期还不上本金时允许展期 1 次
- 展期 = 部分清偿 + 延长4季 + 本金膨胀15%

### 8.4 破产条件

| 条件 | 阈值 |
|------|------|
| 连续贷款违约 | 4 季 |
| 净资产持续为负 | 4 季 |
| 预警阈值 | 2 季开始警告 |

2. 影响力 ≥200: 研发期 -1 季
3. 科技 `research_speed` 效果: 按比例缩短
4. 事件奖励的 `tech_bonus` 点数: 直接减少剩余季度

**科技顾问额外加速**: 每季有 `bonus × 0.4` 概率额外 +1 研发进度（满配40%概率）

### 13.2 AI 行为

- **招募封锁**：招募被封锁期间（recruit_blocked > 0）跳过扩张与额外 power+1

**现金上限与时代缩放**：

### 13.6 AI 崩溃与恢复

**触发条件**：power ≤ 5 **且** cash ≤ 100 同时满足 → 进入 collapsed 状态。

| 参数 | 值 | 说明 |
|------|-----|------|
| power_threshold | 5 | power ≤ 此值 |
| cash_threshold | 100 | cash ≤ 此值 |
| collapsed_power_gain | 1/季 | 瘫痪期间每季缓慢恢复 power（正常为 2~3） |
| presence_decay | 5/季 | 瘫痪期间每季每个地区 ai_presence 衰减 |
| 态度回暖 | +3/季 | 瘫痪期间若 attitude<0 则每季+3（被打服） |
| recovery_seasons | 6 | 达到此季数后一次性注入资源并解除瘫痪 |
| recovery_cash | 400 | 恢复时注入的现金 |
| recovery_power | 20 | 恢复时注入的势力值（受上限 100 封顶） |

**瘫痪期间行为**：
- 跳过正常增长、消费行为、扩张和进攻
- 不累积胜利分
- 仅执行：power 缓慢恢复、存在度衰减、态度回暖、attitude clamp

### 13.7 外资控制度持续性修正器

每季度在 Phase 6.2 自动计算：

```
total_foreign_presence = 所有地区 foreign_capital ai_presence 之和

foreign_control = 0
if total_foreign_presence > 30:
    foreign_control = floor((total_foreign_presence - 30) / 20)
```

- 修正器目标: `foreign_control`，持续 1 季（每季刷新）
- **影响**: 代表外资在整个地区的经济控制力渗透，影响 AI 态度（`floor(fc/10)`）和 power（`floor(fc/12)`）

### 13.8 击败检测

每季 AI 更新结束后（阶段 6.5 战斗后）执行 `CheckFactionDefeat`：

| 击败模式 | 条件 | 说明 |
|---------|------|------|
| **routed**（溃败） | presence ≤ 5 **且** power ≤ 5 | 势力被彻底击溃 |
| **absorbed**（吞并） | 已处于 collapsed **且** presence ≤ 8 **且** cash ≤ 100 | 瘫痪期间未能恢复，被吸收 |

**击败后果**：
- `defeated = true`，此后永久跳过 AI 更新
- power 归零，cash 保留 25%
- 所有地区 ai_presence 清零
- 该势力控制的全部地图格子转入玩家控制

## 14. 战斗系统

### 14.1 战力计算

**玩家战力（编队体系）**：

游戏采用小队编队制，每个小队有独立装备、老兵等级和耐久度：

```
单小队战力 = size × equip.power_mul × veterancy.power_mul × conditionMul
总编队战力 = Σ CalcSquadPower(squad)
未编队护卫 = 剩余护卫 × unassigned_power(0.6)

moraleMul = max(0.3, 士气 × morale_multiplier)
chiefMul  = 1 + 军务主管加成 × 0.4
techMul   = 1 + guard_power_tech_bonus

最终战力 = (总编队战力 + 未编队护卫战力) × moraleMul × chiefMul × techMul
```

> 无编队时兼容模式：全部护卫按 `guards × guard_base_power(1.0) × unassigned_power(0.6)` 计算。

**护卫士气参数**：
| 参数 | 值 |
|------|-----|
| 初始值 | 70 |
| 范围 | 0 ~ 100 |
| 每季自然衰减 | -2（军务主管 bonus 减缓：每点减少衰减 1 点；满配独有：额外 +3 精锐操练） |
| 胜利提升 | +10 |
| 失败损失 | -18 |
| 战力影响 | max(0.3, 士气 × 0.01)，即士气 70 → ×0.7 |

**AI 战力**：
```
基础 = faction.power × 1.0
区域 = 基础 × (1 + 该地区 ai_presence / 200)
```

### 14.2 战斗结算

- 双方战力 ×(0.8~1.2) 随机因子
- 玩家 ≥ AI → 玩家胜

### 14.3 胜负结果

**玩家胜利**：
- 缴获 AI 现金 25%（loot_ratio）
- AI 势力 -8, 态度 -10
- 护卫士气 +10
- 编队：耐久衰减 + 老兵经验累积（Equipment.OnBattleEnd）
- 地区：控制度 +3，AI 存在度 -8
- 若战后 AI power ≤ 5 且 cash ≤ 100 → 触发瘫痪

**玩家失败**：
- 折损护卫 30%（lose_guards_ratio），先扣未编队、再按编队人数从大到小扣
- 士气 -18
- 被抢现金 10%（AI 获得该金额）
- AI 势力 +5
- 地区：控制度 -5，AI 存在度 +7，**治安等级 -1**（仅败方）

事件选项的 `effects` 支持以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| cash | number | 现金增减 |
| gold | number | 黄金增减 |

### 16.4 并发与数量限制

- 固定事件和随机事件**可同季触发**（不互斥）
- 随机事件每季上限：**有固定事件时最多 1 个，否则最多 2 个**
- 模板顺序随机打乱后依次检查，达上限即停

### 16.5 概率修正

```
effectiveChance = event.chance × chanceMultiplier × diff.event_chance_mult
                  × (1 + chance_modifier修正) × 早期缓冲
```

| 修正因子 | 说明 |
|---------|------|
| chanceMultiplier | 干旱保底倍率（见 §16.6） |
| event_chance_mult | 难度系数（easy=0.5, hard=1.0） |
| chance_modifier | 事件自带字段，读取 state 中对应 modifier 值 |
| 早期缓冲 | 1904–1905 年：×0.4（给玩家两年适应期） |

### 16.6 事件干旱保底机制

`event_drought_counter` 追踪连续无**任何事件**（含固定）的季度数。

| 难度 | drought_threshold_2（×1.5） | drought_threshold_3（×2.0） |
|------|---------------------------|---------------------------|
| easy | 4 季 | 5 季 |
| hard | 2 季 | 3 季 |

当 drought_counter 达到阈值后，随机事件概率获得对应倍率加成。任何事件触发后计数器归零。

## 19. 事件-股市联动

部分事件通过 `event_mu_mods` 字段影响股票的漂移率（mu），使股价对历史事件产生真实响应：

- **战争事件**：军需工业股暴涨（mu +大幅正值），铁路/贸易股波动加大
- **经济危机**：银行信托股暴跌（mu 转负），矿业股受冲击
- **和平/贸易事件**：贸易股上涨，军需股回落
- 修正器有持续时间（`duration`），到期后 mu 恢复正常

联动实现在 `systems/stock_engine.lua` 中，股价按 Fair Value Anchored GBM 模型生成，事件 mu_mod 叠加在基础 mu 上。

## 20. 胜利条件

### 20.1 概述

游戏有三条胜利路线，采用**相对领先制**：玩家的胜利分需领先所有 AI 势力一定幅度后方可宣布胜利。宣布后可继续游玩。

```
relative = {
    min_claim_year = 1945,         -- 最早可宣布胜利的年份
    dominance_requires_positive_track = true,
}
```

### 20.2 经济胜利

**阈值**: 1600 VP

**每季增量** = `(floor(cash/2000) + min(floor(gold×0.3), 10) + floor(total_control/15) + floor(total_influence/50)) × war_mod`

| 参数 | 值 | 说明 |
|------|-----|------|
| threshold | 1600 | 经济胜利点阈值 |
| cash_divisor | 2000 | 每 2000 现金 +1 VP/季 |
| gold_multiplier | 0.3 | 每黄金 +0.3 VP/季 |
| gold_vp_cap | 10 | 黄金 VP 贡献上限 10/季 |
| control_divisor | 15 | 每 15 总控制度 +1 VP/季 |
| influence_divisor | 50 | 每 50 总影响力 +1 VP/季 |
| war_mod | 0.6 | 战时经济VP乘数 |
| gate_year | 1930 | 1930年前不结算经济VP |

**快照验证**（达到阈值瞬间需满足）：
- 现金 ≥ 10,000
- 黄金 ≥ 20
- 总控制度 ≥ 80

**领先幅度**: 需领先 AI 经济VP 800 分

### 20.3 军事胜利

**阈值**: 2000 VP

**每季增量** = `(floor(guards×0.25) + floor(morale/25) + floor(total_control/12) + 胜场 + 装备分 + 老兵分) × war_mod`

| 参数 | 值 | 说明 |
|------|-----|------|
| threshold | 2000 | 军事胜利点阈值 |
| guard_multiplier | 0.25 | 每护卫 +0.25 VP/季 |
| morale_divisor | 25 | 每 25 士气 +1 VP/季 |
| control_divisor | 12 | 每 12 总控制度 +1 VP/季 |
| battle_wins_cap | 3 | 每季最多计入 3 场胜利 |
| equip_score_cap | 4 | 装备分上限 |
| equip_tier_multiplier | 0.8 | 每 (tier-1) × 0.8 |
| veterancy_score_cap | 2 | 老兵分上限 |
| war_mod | 1.25 | 战时军事VP乘数 |
| gate_year | 1925 | 1925年前不结算军事VP |

**快照验证**（达到阈值瞬间需满足）：
- 护卫 ≥ 25
- 士气 ≥ 50
- 总控制度 ≥ 100

**领先幅度**: 需领先 AI 军事VP 150 分

### 20.4 支配胜利（Dominance Victory）

**条件**：经济VP + 军事VP 的综合领先

| 参数 | 值 | 说明 |
|------|-----|------|
| dominance_margin | 900 | 需综合领先 AI 900 分 |
| dominance_requires_positive_track | true | 至少一条线需正向领先 |
| ai_military_power_multiplier | 0.12 | AI 军事VP 换算乘数 |

支配胜利要求：
1. 经济VP 领先 **或** 军事VP 领先（至少一条线为正向领先，`dominance_requires_positive_track`）
2. 综合得分（经济VP + 军事VP + 控制度/10 + 影响力/8）领先所有 AI 势力 900 分以上
3. 年份 ≥ 1945（min_claim_year）

## 22. 煤电系统

煤炭作为工业动力资源，连接矿山产能与兵工厂运转。矿山等级越高，采煤效率越高，但工业运营消耗也随之增长。

### 22.1 煤炭产出

```
产量 = floor(基础(15) × 矿山等级乘数 × (1 + (开发度-1) × 0.15) × 控制度系数)

其中:
- 矿山等级乘数 = 1.0 + (最高矿山等级 - 1) × 0.20
- 控制度系数 = max(0.30, 控制度/100)
```

| 最高矿山等级 | 等级乘数 | 基础产量/季 |
|-------------|---------|-----------|
| Lv1 | ×1.0 | 15 |
| Lv2 | ×1.2 | 18 |
| Lv3 | ×1.4 | 21 |
| Lv4 | ×1.6 | 24 |
| Lv5 | ×1.8 | 27 |

### 22.2 煤炭消耗

#### 兵工厂煤耗（刚性，不足则停产）

| 用途 | Lv1 | Lv2 | Lv3 |
|------|-----|-----|-----|
| 兵工厂每季煤耗 | 3 | 5 | 8 |

#### 工业运营煤耗（随矿山最高等级增长，代表蒸汽动力、冶炼等工业消耗）

| 最高矿山等级 | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
|-------------|-----|-----|-----|-----|-----|
| 工业运营煤耗/季 | 0 | 2 | 4 | 7 | 10 |

结算顺序：兵工厂煤耗 → 工业运营煤耗 → 矿山电力分配 → 自动出售。煤炭不足时按此优先级依次扣减。

## 33. 外国矿产操作

### 33.1 概述

玩家可以在被占领的外国领土上侦察并开采矿产资源，流程为：**侦察 → 开采 → 重建**。

### 33.2 侦察（Scout）

| 参数 | 值 | 说明 |
|------|-----|------|
| AP 消耗 | 1 | — |
| 现金消耗 | 150 | — |
| 持续时间 | 1 季 | — |
| 同时进行 | 1 个 | 一次只能侦察一个 tile |

侦察完成后揭示该 tile 的金/铜/煤储量。

### 33.3 开采（Exploit）

| 参数 | 值 | 说明 |
|------|-----|------|
| AP 消耗 | 2 | — |
| 现金消耗 | 800 | — |
| 最低合作分 | 10 | `collaboration_score ≥ 10` |
| 初始损毁率 | 80% | 占领区基础设施严重损毁 |
| 同时开采上限 | 3 | 最多 3 个外国矿并行 |

开采条件：已侦察 + 该国处于被占领状态 + 合作分达标。

### 33.4 重建（Rebuild）

| 参数 | 值 | 说明 |
|------|-----|------|
| AP 消耗 | 1 | — |
| 现金消耗 | 500 | — |
| 修复量 | 10%/次 | 损毁率 -10% |
| 最低损毁率 | 10% | 永远无法完全恢复 |

### 33.5 产出计算

```
有效比率 = (1 - 损毁率) × output_base_ratio(0.5)
产出 = 国内同级基础产出 × 有效比率（至少 1，不超过剩余储量）
```

外国矿基础产出为国内矿的 **50%**，实际产出还受损毁率影响。

### 33.6 终止条件

每季度检查有效性，以下情况终止开采：

- 该国被解放（`sovereign` 恢复为 `original`）→ 矿权收回
- 储量全部耗尽（金+铜+煤 = 0）

## 35. 掠夺系统与声誉

### 35.1 概述

玩家可通过武力掠夺积累前期资本，作为采矿路线的高风险替代方案。掠夺路线收益更高，但伴随声誉代价，中后期需要转型。掠夺行动位于交易弹窗中。

| 夺取矿脉 | 强占 AI 矿产 | 2 | 120 | 3季 | 14 | -15 |
| 勒索外资 | 威胁外国资本 | 2 | 150 | 2季 | 18 | -10 |

**行动详情**：

| 行动 | 成功奖励 | 失败惩罚 |
|------|---------|---------|

| 勒索外资 | 400-800 克朗（×通胀） | 外资 aggression +15（持续 4 季） |

### 35.3 掠夺判定

使用轻量级力量对比检定（不走完整 `Combat.Resolve`）：

```
成功率 = clamp(玩家战力 / (难度 × 随机因子), 0.15, 0.90)
```

**玩家战力公式**：
```
totalPower = 编队战力总和 + 未编队护卫 × 0.6
playerPower = totalPower × max(0.3, morale × 0.01) × (1 + chiefBonus × 0.4) × (1 + techBonus)
```

**声誉范围**: -100 ~ 0，初始 0，每季自然恢复 +2

**掠夺甜区: 10-20 护卫**

| 护卫数 | 额外军费/季 | 劫掠成功率 | 掠夺净值/季 |

## 36. 称号系统

称号是一套成就式收集系统，为玩家在军事、掠夺、经济、证券、综合五大维度的长期投入提供里程碑奖励反馈。称号偏向中后期解锁，每个类别设有一个入门级称号降低门槛。

### 36.1 系统概述

| 参数 | 值 |
|------|-----|
| 称号总数 | 18 |
| 类别数 | 5（军事 / 掠夺 / 经济 / 证券 / 综合） |
| 检查时机 | 每回合结算阶段 Phase 8.9（位于事件处理之后、胜利判定之前） |
| 存储位置 | `state.titles_unlocked`（id → 解锁回合号）、`state.titles_new`（当回合新增） |
| 是否可失去 | 否，一旦解锁永久保留 |

### 36.2 类别定义

| 类别 | 图标 | 称号数 | 侧重 |
|------|------|--------|------|
| 军事 | ⚔️ | 4 | 进攻次数、胜场数、防御力量 |
| 掠夺 | 🏴 | 3 | 掠夺成功次数、声誉极端值 |
| 经济 | 💰 | 4 | 矿山数量、现金储备、贷款与通胀抗性 |
| 证券 | 📈 | 4 | 交易笔数、操纵次数、做空盈利 |
| 综合 | 🏛️ | 3 | 科技研发、家族规模、存活时长 |

### 36.4 统计计数器

称号系统依赖 `state.stats` 中的额外计数器追踪玩家行为：

| 计数器 | 累加位置 | 用途 |
|--------|---------|------|
| `attacks_initiated` | `combat.lua` → PlayerAttack | 主动攻击次数 |
| `plunder_successes` | `combat.lua` → RaidCaravan/SeizeVein/ExtortForeign | 掠夺成功次数 |
| `manipulation_successes` | `stock_engine.lua` → MarketPump/MarketDump/CoordinatedOp | 股市操纵成功次数 |
| `trades_completed` | `stock_engine.lua` → Buy/Sell | 股票交易笔数 |
| `short_profit_total` | `stock_engine.lua` → CloseShort | 做空累计盈利 |

其余称号直接读取 `state` 中已有字段（如 `battle_wins_total`、`cash`、`reputation`）。

### 36.5 结算流程

```
回合结算 Phase 8.9
  ↓
require("systems.titles").Check(state)
  ↓
遍历 18 个称号 → pcall 执行 check(state, stats)
  ↓
新解锁的称号 → 写入 state.titles_unlocked[id] = turn_count
                → 写入 state.titles_new[id] = true
  ↓
返回新解锁列表 → turn_engine 将每个新称号写入日志（🏅 前缀）
```

### 36.6 存档兼容

- 序列化时保存 `stats` 和 `titles_unlocked` 两个字段
- 反序列化时为缺失字段提供默认值（旧存档自动迁移）
- `titles_new` 为运行时临时字段，不持久化

### 36.7 UI 展示

称号卡片位于世界页「报告」子标签中，排列在季报摘要与全球指标之间。详见 UI 规格文档。

- 仅当玩家解锁过至少一个称号时才显示
- 新解锁的称号用金色高亮提示
- 按类别分组展示进度（已解锁数 / 总数）
