# 第二梯队系统 + 音频系统 内容优化方案

> 目标：在不大幅重构架构的前提下，通过**纯数据扩展 + 少量系统逻辑补充**，显著提升5个系统的内容深度和策略选择感。

---

## 一、家族管理 — 特质系统

### 现状

- 成员仅靠5个数值属性(3-8随机)区分，训练池成员千人一面
- 隐藏属性(忠诚/腐败/激进)只有模糊文本提示，缺乏 gameplay 影响
- `title` 字段纯装饰，`bio` 字段只在详情弹窗展示

### 优化：为家族成员增加**独特特质(Trait)**

每位成员生成时随机获得 **1个特质**，提供岗位相关的独特加成或特殊效果。

#### 特质设计（12个，按偏好岗位分组）

| 特质ID | 名称 | 效果 | 偏好岗位 |
|--------|------|------|---------|
| `born_miner` | 矿脉直觉 | 矿山产出+10% | 矿业总监 |
| `geologist` | 地质学家 | 勘探成功率+15% | 矿业总监 |
| `iron_fist` | 铁腕治军 | 士气衰减减半 | 军事参谋 |
| `veteran_commander` | 沙场宿将 | 编队经验获取+30% | 军事参谋 |
| `silver_tongue` | 巧舌如簧 | 外交行动AP-1(最低1) | 外交官 |
| `local_network` | 地方人脉 | 控制度自然增长+1/季 | 内政总监 |
| `tax_expert` | 税务专家 | 税率减免3% | 内政总监 |
| `market_sense` | 市场嗅觉 | 股票买卖手续费-20% | 文化顾问 |
| `patron_of_arts` | 艺术赞助人 | 声誉自然恢复+1/季 | 文化顾问 |
| `tech_savant` | 技术奇才 | 科研速度+15% | 科技顾问 |
| `arms_dealer` | 军火掮客 | 贸易订单价格+10% | (通用) |
| `frugal` | 精打细算 | 全局维护费-5% | (通用) |

#### 初始成员预设

- 族长 尼古拉 → `local_network`（地方人脉）—— 契合老家主深耕本地的人设
- 长子 马尔科 → `iron_fist`（铁腕治军）—— 契合策略7、野心7的激进性格
- 侄女 莉娜 → `tech_savant`（技术奇才）—— 契合知识8的学者背景

#### 特质机制规则

- 每位成员**终身绑定1个特质**，不可更换
- 特质效果**仅在成员被任命到对应岗位时生效**（通用特质任意岗位均生效）
- 训练新成员时从12个特质中随机抽取1个（避免与现有成员重复）
- Reroll（属性重随）**不影响特质**，保持特质稳定性
- UI 显示：成员卡片右上角显示特质 `UI.Chip`，详情弹窗中展示完整效果描述

#### 改动文件

| 文件 | 改动内容 |
|------|---------|
| `data/families_data.lua` | 新增 `TRAITS` 常量表（12个特质定义）；`CreateTraineeTemplate()` 中随机分配特质；初始成员预设特质 |
| `game_state.lua` | 新增 `GetActiveTraitEffect(state, effectType)` 查询当前生效特质加成；`GetPositionBonus()` 中叠加特质效果 |
| `ui/ui_family.lua` | 成员卡片显示特质标签；详情弹窗显示特质描述；候选人弹窗显示特质辅助决策 |
| `utils/save_load.lua` | 成员序列化新增 `trait` 字段 |

## 二、装备系统 — 支援装备（副武器槽）

### 现状

- 6个装备纯线性升级（步枪→精锐套件），只有纵向选择
- 每个编队单装备槽，无搭配策略
- 铜消耗是唯一的资源约束

### 优化：新增**支援装备**作为编队第二装备槽

保持现有6级主武器不变，新增4种支援装备。支援装备**不提供战力倍率**，而是提供**特殊效果**，与主武器形成功能互补。

#### 支援装备设计（4种）

| ID | 名称 | 效果 | 生产费 | 回合 | 维护 | 铜耗 | 解锁科技 |
|----|------|------|--------|-----|------|------|---------|
| `medkit` | 战地医疗包 | 该编队战斗损员-25% | 150 | 2 | 8 | 2 | `c2_field_fortify` |
| `scout_gear` | 侦察装具 | 该编队参与远征时伤害+15% | 200 | 2 | 10 | 4 | `c3_machine_gun` |
| `field_radio` | 战地电台 | 该编队护送贸易时安全+10% | 280 | 3 | 12 | 6 | `c5_motorized` |
| `siege_kit` | 攻城器材 | 该编队对大国远征伤害+20% | 400 | 4 | 18 | 10 | `c7_elite_force` |

#### 设计原则

- 支援装备与主武器**独立生产**，共用工厂/外包产线
- 支援装备有独立的**耐久度和维修**机制（复用现有修理框架）
- 支援装备**不计入编队战力**（CalcSquadPower 不变），仅在特定场景提供效果加成
- 编队可选择**不装备支援装备**（副槽为空合法）

#### 改动文件

| 文件 | 改动内容 |
|------|---------|
| `data/equipment_data.lua` | 新增 `SUPPORT_CATALOG`（4条目）、`SUPPORT_TIER_ORDER`、`SUPPORT_TECH_UNLOCK` |
| `data/balance.lua` | `COPPER` 部分增加支援装备铜消耗映射 |
| `systems/equipment.lua` | 编队增加 `support_equip_id` 字段；新增 `AssignSupport()` / `RemoveSupport()`；`CalcMaintenanceCost()` 计入支援装备维护 |
| `systems/combat.lua` | 损员计算时检查编队 `medkit` 效果 |
| `systems/expedition.lua` | 远征伤害计算时检查 `scout_gear` / `siege_kit` 效果 |
| `systems/trade.lua` | 护送安全计算时检查 `field_radio` 效果 |
| `ui/ui_equipment_modals.lua` | 编队卡片新增支援槽显示；生产弹窗分"主武器/支援装备"两组；库存列表分区 |
| `ui/ui_military.lua` | 编队概览中显示支援装备图标 |
| `utils/save_load.lua` | 编队序列化新增 `support_equip_id`；库存兼容支援装备条目 |

## 三、贸易系统 — 民用商品订单

### 现状

- 所有订单都是军火（步枪→精锐套件），品类单一
- 和平时期只有2个订单模板（民用步枪、改良步枪），内容感薄
- 贸易系统本质上是"装备生产→卖出"的单一循环

### 优化：新增消耗矿产资源的**民用商品订单**

在现有军火订单之外，增加不依赖装备库存的民用商品订单。民用订单消耗矿产资源（金/铜/煤）而非装备，拓宽贸易的资源决策维度。

#### 民用订单模板设计（6个）

**和平期模板（3个）：**

| 模板 | 商品名 | 消耗资源 | 数量范围 | 每单位报酬 | 交货期 | 风险 |
|------|--------|---------|---------|-----------|--------|------|
| 铜锭出口 | 精炼铜锭 | 铜×N | 5-15 | 12 | 3回合 | 低 |
| 煤炭供应 | 工业煤炭 | 煤×N | 10-30 | 7 | 3回合 | 低 |
| 黄金交割 | 标准金锭 | 金×N | 2-6 | 55 | 2回合 | 低 |

**战时模板（3个）：**

| 模板 | 商品名 | 消耗资源 | 数量范围 | 每单位报酬 | 交货期 | 风险 |
|------|--------|---------|---------|-----------|--------|------|
| 战略矿产 | 混合矿产 | 铜×N + 煤×M | 各5-10 | 20/批 | 4回合 | 中 |
| 贵金属急单 | 黄金紧急交割 | 金×N | 3-10 | 80 | 2回合 | 中 |
| 工业原料包 | 综合原料 | 金×1 + 铜×8 + 煤×15 | 固定 | 350/批 | 4回合 | 高 |

#### 订单生成规则

- 每季订单池中，军火订单与民用订单按 **60:40** 的概率混合生成
- 民用订单使用**相同的路线系统**（距离、安全度、运费均复用）
- 民用订单**不需要装备库存检查**，改为下单时检查矿产库存是否足够
- 运输失败时，已扣除的矿产资源**不退还**（与军火订单失去装备一致）

#### 订单数据结构扩展

```lua
-- 现有军火订单
order = {
    order_type = "military",        -- 新增字段
    items_required = {{equip_id = "rifle", qty = 5}},
    -- ...其他字段不变
}

-- 新增民用订单
order = {
    order_type = "civil",           -- 新增字段
    resources_required = {          -- 新增字段（替代 items_required）
        {resource = "copper", qty = 10},
    },
    -- payment_base, deadline_turns, risk_level 等字段复用
}
```

#### 改动文件

| 文件 | 改动内容 |
|------|---------|
| `data/trade_routes_data.lua` | 新增 `CIVIL_PEACE_TEMPLATES`（3个）和 `CIVIL_WAR_TEMPLATES`（3个） |
| `data/balance.lua` | 新增 `CIVIL_TRADE` 配置段（生成概率 0.4、报酬通胀指数等） |
| `systems/trade.lua` | `GenerateOrders()` 按概率混合生成两类订单；新增 `AllocateResources(state, orderId)` 处理民用订单资源扣除；`QuickFulfill()` 适配民用类型 |
| `ui/ui_trade.lua` | 订单卡片根据 `order_type` 切换显示（军火显示装备、民用显示资源图标+数量）；可选：顶部增加"全部/军火/民用"筛选标签 |
| `utils/save_load.lua` | 订单序列化兼容 `order_type` 和 `resources_required` 字段 |

## 四、海外作战 — 据点升级 + 外交联动

### 现状

- 仅有侦察(1AP)→开采(2AP)→修复(1AP)三个动作，377行，是最薄弱的系统
- 与其他系统（大国外交、贸易）缺乏联动
- 据点产出固定为国内基础的50%，没有成长空间

### 优化：增加**据点升级路线**、**外交联动**和**专属随机事件**

#### 据点升级（3级）

| 等级 | 名称 | 升级费 | AP | 产出比 | 初始损伤 | 额外效果 |
|------|------|--------|-----|--------|---------|---------|
| 1 | 临时矿点 | (开采时自动) | - | 50% | 80% | - |
| 2 | 稳定矿场 | 600 | 1 | 70% | 降至50% | - |
| 3 | 工业矿区 | 1200 | 2 | 90% | 降至30% | 每季额外+3铜 |

- 升级条件：据点已存在 + 当前等级 < 3 + 有足够现金和AP
- 升级为**即时生效**（不需要等待回合）
- 修复(Rebuild)仍然独立存在，用于战时损伤恢复

#### 外交联动

| 条件 | 效果 |
|------|------|
| 与据点所在国宗主国关系 ≥ 20 | 开采/升级费用-20% |
| 宗主国处于战争中 | 据点每季15%概率被破坏（损伤+20%） |
| 玩家占领该国（sovereign="bosnia"） | 升级费减半 |
| 合作度 ≥ 30 | 开采跳过合作度门槛检查（已有）+ 最大据点数+1 |

#### 专属随机事件（3个）

| 事件ID | 名称 | 触发条件 | 效果 |
|--------|------|---------|------|
| `foreign_vein_discovery` | 矿脉发现 | 有已侦察但未开采的矿脉 | 随机一个已侦察矿脉储量+30% |
| `foreign_local_conflict` | 当地冲突 | 有活跃据点 | 随机一个据点损伤+25%，生成修复提示 |
| `foreign_tech_cooperation` | 技术合作 | 有≥2个活跃据点 + 科技顾问在岗 | 全部据点产出+20%，持续2季 |

#### 改动文件

| 文件 | 改动内容 |
|------|---------|
| `data/balance.lua` | `FOREIGN_OPS` 增加 `upgrade_levels` 配置（费用、产出比、损伤等） |
| `data/events_data.lua` | 新增3个海外经营类随机事件 |
| `systems/foreign_ops.lua` | 据点数据增加 `level` 字段（默认1）；新增 `CanUpgrade()` / `UpgradeOutpost()`；`CalcOutput()` 根据 `level` 调整产出比；`ValidateActive()` 增加战时破坏检查 |
| `ui/ui_world.lua` | 据点信息显示等级标识和升级按钮；升级按钮灰态提示（条件不足时） |
| `utils/save_load.lua` | 据点序列化新增 `level` 字段 |

## 五、音频系统 — 时代BGM + 情境音效

### 现状

- 仅2首BGM（`bgm_peace` / `bgm_war`），跨越50年5个时代无变化
- 19个音效已覆盖基础UI交互和核心战斗反馈
- 缺少贸易、远征、家族、股票等系统的操作反馈音效
- 胜利/失败没有专属BGM

### 优化：5首时代BGM + 2首结局BGM + 11个新系统音效

#### 时代BGM（7首）

| BGM ID | 名称 | 对应时期 | 风格描述（生成prompt参考） |
|--------|------|---------|-------------------------|
| `bgm_belle_epoque` | 美好年代 | 1904-1913 | 维也纳华尔兹风格，弦乐为主，优雅从容，带有一丝东欧民族色彩 |
| `bgm_great_war` | 大战风云 | 1914-1918 | 紧张军事进行曲，铜管为主，定音鼓节奏，压迫感强 |
| `bgm_interwar` | 战间迷局 | 1919-1929 | 爵士元素混合古典弦乐，自信但暗流涌动，钢琴间奏 |
| `bgm_depression` | 萧条阴影 | 1930-1938 | 低沉大提琴主旋律，缓慢节奏，压抑不安，偶尔小提琴独奏 |
| `bgm_world_war` | 二战烽火 | 1939-1955 | 史诗管弦乐，命运交响，节奏交替（紧张→舒缓→高潮） |
| `bgm_victory` | 胜利凯歌 | 游戏胜利 | 辉煌庄严的管弦乐，铜管齐鸣，终曲感 |
| `bgm_defeat` | 落幕挽歌 | 游戏失败 | 哀伤但不绝望的弦乐，钢琴收尾，余韵悠长 |

#### 新增系统音效（11个）

| 音效ID | 触发场景 | 风格描述（生成prompt参考） |
|--------|---------|-------------------------|
| `trade_order_accept` | 接受贸易订单 | 羽毛笔签约声 + 轻微印章声 |
| `trade_delivery` | 贸易成功交付 | 货车到达 + 木箱卸货声 |
| `trade_failed` | 贸易运输失败 | 木箱碎裂 + 短促低沉号角 |
| `expedition_launch` | 发起远征 | 军号吹响 + 整齐步伐声 |
| `expedition_victory` | 远征征服成功 | 士兵欢呼 + 旗帜飘扬声 |
| `title_unlock` | 称号解锁 | 勋章授予声 + 短促铜管 fanfare |
| `family_train` | 开始培养家族成员 | 翻书声 + 墨水笔书写声 |
| `family_assign` | 任命岗位 | 正式印章盖章声 |
| `stock_buy` | 股票买入 | 老式收银机铃声 |
| `stock_sell` | 股票卖出 | 硬币倾泻声 + 结算铃 |
| `plunder_success` | 掠夺成功 | 金属碰撞声 + 急促脚步远去 |

#### BGM切换逻辑

```
现有逻辑:
  era.war_stripe == true → bgm_war
  else                   → bgm_peace

优化后:
  按 era.id 选择对应时代 BGM:
    belle_epoque → bgm_belle_epoque
    great_war    → bgm_great_war
    interwar     → bgm_interwar
    depression   → bgm_depression
    world_war    → bgm_world_war
  
  游戏结局由 ui_ending_modal 控制:
    胜利 → bgm_victory
    失败 → bgm_defeat
```

#### 资源生成方式

- BGM：使用 `text_to_music` 工具逐首生成（每首约30-60秒循环）
- 音效：使用 `batch_sound_effects` 工具批量生成（每个1-3秒）
- 文件存放：`assets/Sounds/Music/` 和 `assets/Sounds/Effects/`

## 实施优先级排序

按**改动范围小→大、风险低→高**排序：

| 顺序 | 系统 | 改动规模 | 新增数据量 | 理由 |
|------|------|---------|-----------|------|
| 1 | 音频系统 | 小 | 7 BGM + 11 SFX | 纯增量，零风险，立竿见影提升沉浸感 |
| 2 | 家族特质 | 小-中 | 12个特质定义 | 数据驱动，对现有逻辑侵入最小 |
| 3 | 海外经营深化 | 中 | 3级升级 + 3个事件 | 在最薄弱的系统上补短板，投入产出比高 |
| 4 | 民用贸易 | 中 | 6个订单模板 | 需要新的资源扣除逻辑，但运输框架完全复用 |
| 5 | 支援装备 | 中-大 | 4种支援装备 | 涉及战斗/远征/贸易多个系统的效果计算，联动最广 |
