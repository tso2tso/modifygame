# 百年萨拉热窝：黄金家族 — 机制冗余审查报告（修订版）

> 审查视角：游戏策划 + 玩家体验
> 审查重点：**机制是否重复冗余**，不纠结单个数值多少
> 代码版本：2026-05-09

---

## 总评

游戏系统深度极佳，但存在 **6 处明确的机制冗余**（两套系统做同一件事）和 **4 处死代码**（有实现但无效果）。此外确认了 2 项需要新增的机制（声誉恢复、家族年龄退休）。

**核心诊断：不是数值太多，而是同一件事被重复建模了。**

## 一、确认删除：补给系统 🔴

### 代码证据

| 系统 | 是否读取 `military.supply` | 结论 |
|------|--------------------------|------|
| `combat.lua` | ❌ 完全不读取 | 战斗力无关 |
| `expedition.lua` | ❌ 只用了 modifier 不用实际值 | 远征无关 |
| `economy.lua` | ✅ 计算 `supply_expense` | 唯一作用：花钱 |
| `ui_military.lua` | ✅ 显示+补充按钮 | 唯一交互：花钱+AP |

**结论**：补给 = 军事维护费的别名。删除后将 `supply_expense` 并入 `military_expense`，减少 1 个资源 + 1 个无用操作。

### 改动范围

| 文件 | 改动 |
|------|------|
| `economy.lua` | 删除 `supply_expense` 独立行，并入 `military_expense` |
| `ui_military.lua` | 删除补给显示行、补充按钮、`_OnResupply()` |
| `balance.lua` | 删除 `supply_per_guard`、`supply_cost` 参数 |
| `game_state.lua` | 初始化时不再创建 `military.supply` |
| `ui_industry.lua` | 如有补给相关显示一并删除 |

## 二、确认合并：影响力 → 控制度 🔴

### 代码证据

| 指标 | 来源 | 实际效果 |
|------|------|---------|
| **控制度** (0-100) | 战斗胜利+3/败-5、远征占领 | 税收减免、矿山收入、胜利分、区域工业收入 |
| **影响力** (0-∞) | 每季被动+N、文化顾问加成 | 总影响力≥300→VP+5（一次性），**其余无效果** |

**关键发现**：`economy.lua` 中影响力只做了**被动累加**，没有转化为控制度的路径。影响力是一个**半成品机制**——积累了但从不消费。

### 合并设计

将影响力的"软实力"概念内化到控制度的增长方式中：

| 原机制 | 合并后 |
|--------|--------|
| 文化行动增加影响力 | 文化行动增加控制度（+2/次，比军事的+3略少） |
| 影响力被动累加 | 删除，不再有独立影响力数值 |
| 影响力≥300→VP+5 | 改为总控制度≥350→VP+5 |
| 文化顾问加成影响力 | 文化顾问加成控制度增长速度 |

**净减少**：5 个区域数值（5 区 × 影响力）+ 相关 UI 显示

### 改动范围

| 文件 | 改动 |
|------|------|
| `economy.lua` | 删除影响力被动累加逻辑 |
| `turn_engine.lua` | 删除影响力衰减阶段（Stage 4.5）|
| `game_state.lua` | 区域初始化不再包含 `influence` 字段 |
| `ui_world.lua` | 删除影响力显示列 |
| 胜利条件相关 | 将影响力阈值改为控制度阈值 |

## 三、机制冗余 #1：三套"声誉"系统 🔴

### 代码证据

游戏中存在 **三个独立的"玩家信誉"追踪系统**，互不相通：

| 系统 | 字段 | 范围 | 增减来源 | 影响 |
|------|------|------|---------|------|
| **掠夺声誉** | `state.reputation` | -100~0 | 掠夺-15~-20，自然恢复+2/季 | 贸易惩罚5%~40%、AI攻击概率+20%~50% |
| **贸易信誉** | `state.trade.reputation` | -10~+10 | 交付成功+0.05，超时-0.05 | 订单价格+5%/点、路线安全+2%/点 |
| **股市可信度** | `Balance.CREDIBILITY` | 0~100 | 操纵成功/失败 | 操纵成功率 |

**玩家视角的困惑**：
- "声誉"和"贸易信誉"是两个东西？掠夺会影响贸易吗？（不会）
- 股市可信度和声誉有关系吗？（没有）
- 三套系统各有独立的增减规则、独立的 UI 显示、独立的效果——但概念完全重叠

### 建议：合并为统一声誉系统

**合并方案**：

| 保留 | 删除 | 理由 |
|------|------|------|
| `state.reputation` (-100~+100) | `state.trade.reputation` | 贸易信誉并入统一声誉 |
| 统一声誉 | `Balance.CREDIBILITY` | 股市可信度并入统一声誉 |

**合并后效果映射**：
- 声誉 > 0：贸易价格加成、路线安全加成（原贸易信誉的功能）
- 声誉 < 0：贸易惩罚、AI 攻击概率上升（原掠夺声誉的功能）
- 声誉影响股市操纵成功率（原可信度的功能）
- 成功交付+1、掠夺-15、操纵失败-5（统一增减）

**净减少**：2 个独立系统 → 1 个统一系统

## 四、机制冗余 #2：侵略度 vs 声誉 🟡

### 代码证据

| 系统 | 字段 | 衡量什么 | 效果 |
|------|------|---------|------|
| **侵略度** | `state.expeditions.aggression_counter` | 远征攻击性 | 经济制裁(≥5)、军事干预(≥8) |
| **掠夺声誉** | `state.reputation` | 掠夺恶行 | 贸易惩罚、AI攻击概率 |

两者都在衡量"玩家的攻击性行为"，但互不影响：
- 掠夺降低声誉但不增加侵略度
- 远征增加侵略度但不降低声誉

**玩家困惑**："我掠夺了 10 次被标为'臭名昭著'，但远征系统完全不管？反过来，我远征占领了 5 个地区触发制裁，但声誉还是清白的？"

### 建议

将侵略度作为声誉的一个**子效果**（声誉降到某阈值时自动触发制裁），而非独立追踪：

```
统一声誉 ≤ -30 → 触发贸易限制（原侵略度效果1）
统一声誉 ≤ -60 → 触发经济制裁（原侵略度效果2）
统一声誉 ≤ -80 → 触发军事干预（原侵略度效果3）
```

远征行动同时降低声誉（而非独立增加侵略度）。

## 七、新增机制 #1：声誉恢复路径 🔴

### 当前状态

| 声誉变化 | 来源 | 幅度 |
|---------|------|------|
| **减少** | 掠夺成功 -15~-20、掠夺失败 -8~-12、股市操纵失败 -5 | 显著 |
| **恢复** | 每季自然 +2、`rep_recovery_bonus` modifier | 缓慢 |
| **主动恢复** | ❌ **不存在** | — |

**问题**：声誉是单向恶化的。掠夺一次 -20，自然恢复需要 10 季（2.5 年）。但游戏总时长约 200 季（50 年），掠夺 10 次就消耗了 100 季的恢复时间——实质上声誉不可逆。

### 建议：增加主动声誉恢复手段

| 手段 | 成本 | 效果 | 冷却 |
|------|------|------|------|
| **公益捐赠** | 💰2000 + ⚡1AP | 声誉 +5 | 2 季 |
| **公开道歉声明** | ⚡2AP | 声誉 +8，但好感度 -3（示弱） | 4 季 |
| **社区建设** | 💰1000 + 👷10工人 | 声誉 +3，持续 3 季 | 无 |

**实现位置**：新增到 `player_actions_gp.lua` 或独立的 `reputation_actions.lua`

## 八、新增机制 #2：家族成员年龄与退休 🔴

### 当前状态

家族成员数据结构**完全没有年龄概念**：

```lua
-- 当前结构（families_data.lua）
{
    id = "patriarch",
    name = "尼古拉·科瓦奇",
    attrs = { management=7, strategy=5, charisma=7, knowledge=5, ambition=6 },
    hidden = { corruption=2, loyalty=9, radical=3 },
    position = nil,
    status = "active",      -- 只有 active / disabled
    -- ❌ 无 birth_year
    -- ❌ 无 age
    -- ❌ 无 retirement 逻辑
}
```

**问题**：家族成员永远不会老去、退休或死亡。一个开局安排好的"优秀矿业总监"可以干 50 年不换。这削弱了家族管理的策略深度——没有继任规划的压力。

### 建议：增加年龄与退休机制

**数据扩展**：

```lua
{
    id = "patriarch",
    name = "尼古拉·科瓦奇",
    birth_year = 1860,       -- 新增：出生年份
    -- age 由 state.year - birth_year 动态计算，不单独存储
    ...
}
```

**核心规则**：

| 年龄段 | 效果 |
|--------|------|
| < 30 | 正常（年轻有为） |
| 30-49 | 正常（壮年） |
| 50-59 | 属性 -1（体力衰退），标签"年迈" |
| ≥ 60 | **强制退休**，清除职位，状态变为 `retired` |

**退休流程**：

1. `turn_engine.lua` 每季检查所有成员年龄
2. 达到 60 岁 → 弹出事件通知："尼古拉·科瓦奇年事已高，宣布退休"
3. 清除其职位（`position = nil`）
4. 状态改为 `retired`（不可再分配职位）
5. 如果该职位无人接替 → 提示玩家安排继任者

**继任者来源**：

| 方式 | 条件 | 说明 |
|------|------|------|
| 现有成员调任 | 有空闲成员 | 需要适应期 |
| 新成员招募 | 💰3000 + ⚡2AP | 随机属性，需要培养 |
| 退休成员推荐 | 退休时自动 | 继承部分属性倾向，适应期减半 |

**策略深度增加**：
- 玩家需要提前培养继任者（而非一套阵容用到底）
- 年长成员经验丰富但剩余任期短，年轻成员需要培养但可用更久
- 50-59 岁成员是否提前替换？（属性已衰退，但继任者需要适应期）

### 改动范围

| 文件 | 改动 |
|------|------|
| `data/families_data.lua` | 每个成员增加 `birth_year` 字段 |
| `game_state.lua` | 增加 `GetMemberAge()`、`RetireMember()` 函数 |
| `turn_engine.lua` | 每季年龄检查阶段（Stage 8 后新增） |
| `ui_menu.lua` 或家族 UI | 显示年龄、退休倒计时 |
| `balance.lua` | 增加 `Balance.FAMILY.retirement_age = 60`、`aging_debuff_age = 50` |

以下 modifier key 此前被列为"未设置"，现已确认有设置来源：

## 总结

这次审查聚焦于**机制冗余**而非数值数量，发现的核心问题是：

**"同一概念被重复建模"**——声誉有 3 套、攻击性有 2 套、区域实力有 2 套（影响力+控制度）。这不是数值太多的问题，而是设计层面需要明确"一个概念只用一个系统追踪"。

**五项行动**：
1. 🗑️ 删补给（无效机制）
2. 🔗 合并影响力→控制度（概念重叠）
3. 🔗 合并三套声誉→统一声誉（机制冗余）
4. ➕ 增加声誉恢复手段（缺失的设计闭环）
5. ➕ 增加家族年龄退休（缺失的策略维度）

所有 P0 合计约 **350 行改动**，不涉及架构变更。
