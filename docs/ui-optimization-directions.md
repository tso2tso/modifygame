# 当前 UI 设计优化方向分析

> 基于当前截图、`scripts/ui/` 实现、`scripts/config.lua` 视觉 token，以及现有 `docs/ui-spec.md` / `docs/map-design.md` 的对照分析。

## 1. 总体判断

当前 UI 已经形成了清晰的主题方向：深煤棕背景、旧金强调色、羊皮纸卡片、竖屏移动端布局，整体符合“工业帝国主义时代的家族账簿”定位。核心问题不在风格缺失，而在 **信息密度、层级优先级、交互可见性和系统复杂度承载** 上。

从截图看，游戏已经同时承载资源、AP、事件、矿业、市场、武装、世界地图、大国系统等多条系统线。现在的界面更像把每个系统“都展示出来”，但还没有充分区分：

- 哪些信息是本回合必须立即决策的。
- 哪些信息只是诊断、解释或长期规划。
- 哪些操作是高频入口，哪些应收进详情或弹窗。
- 哪些数值需要突出，哪些应该弱化或折叠。

因此优化方向应以 **降低认知负担、提高决策效率、统一交互语义** 为主，而不是单纯换配色或增加装饰。

## 2. 当前优势

### 2.1 视觉主题已经稳定

`scripts/config.lua` 中已经定义了完整的颜色、字号、间距、圆角和时代主题。深色背景与旧金强调色在截图中辨识度较高，适合历史经营题材。

尤其是：

- `Config.ERAS` 允许随年代变化强调色和战争遮罩，具备长期叙事潜力。
- `Config.COLORS` 区分了 `bg_base`、`bg_surface`、`bg_elevated`、`paper_dark`、`paper_mid` 等层级。
- `Config.SIZE` 已经把顶栏、AP 栏、底部导航、卡片间距、按钮高度集中配置，便于后续统一瘦身。

### 2.2 页面架构清楚

`ui_manager.lua` 采用固定顶栏、内容区、底部导航的移动端结构：

- 顶部：全局资源、时间、AP、安全。
- 中部：Dashboard 或五个深度页。
- 底部：家族、产业、市场、武装、世界。

这个结构对移动端经营游戏是合理的，用户能快速建立“顶部看状态、底部切系统、中间做决策”的心智模型。

### 2.3 系统入口基本完整

截图中的 Dashboard、市场、武装、世界页已经覆盖核心玩法入口。尤其 Dashboard 已经具备：

- 当前事件。
- 焦点矿山。
- 快速行动。
- 本季概览。
- 结束回合。

这说明当前问题不是缺入口，而是入口优先级和信息布局需要进一步收敛。

## 3. 核心问题

### 3.1 顶栏信息过密，关键资源不够分层

截图中顶部区域同时展示现金、广告按钮、黄金、产金、声望、净资产、年份、日期、时代、安全等级、AP、AP 点、购买 AP、设置、回首页等信息。`ui_top_bar.lua` 的实现也验证了这些内容都被塞在两行固定区域内。

问题：

- 资源图标和数值太小，移动端扫视成本高。
- 现金、黄金、产金、声望、净资产视觉权重接近，但决策优先级不同。
- 广告按钮位于核心资源组中间，容易破坏资源阅读连续性。
- 安全等级和 AP 同属本回合行动约束，但视觉上不如资源区清楚。

优化方向：

- 将顶部资源分为“主资源”和“次级资源”两级。建议主资源只保留现金、黄金、AP；净资产、产金、声望改为小型二级状态或点击展开。
- 广告按钮从资源组中移出，放到 `+` AP 或设置附近，避免看起来像资源类型。
- AP 栏应成为本回合行动状态的核心：已用/总量、可购买、惩罚原因、安全影响应更明确。
- 对负现金流、低 AP、低安全等风险状态使用更直接的红/橙状态条，而不是仅靠小字。

### 3.2 Dashboard 更像信息堆叠，而不是回合决策面板

Dashboard 现在按事件、焦点卡、快速行动、本季概览、结束回合纵向排列。截图中首屏会同时出现事件、矿山图片、四个快速操作和概览局部，信息很多，但不一定告诉玩家“现在最应该做什么”。

问题：

- 当前事件和焦点矿山都很醒目，主次会竞争。
- 快速行动的“可执行”标签重复，占用空间但帮助有限。
- 本季概览在底部，现金流、负债率、民心等关键风险可能被淹没。
- 结束回合按钮离主要事件较远，完成决策后的路径略长。

优化方向：

- Dashboard 首屏应优先服务“本回合决策”：待处理事件、重大风险、推荐行动、结束回合。
- 焦点矿山可从大图卡片改为更紧凑的“本季生产焦点”，图片高度降低或仅在无事件时放大。
- 快速行动改为“推荐行动 + 更多行动”。例如只展示 2 个系统推荐按钮，其余进入操作面板。
- 本季概览中的现金流、负债率、民心、影响力可提升为“风险摘要条”，放在快速行动之前。

### 3.3 世界地图可玩性强，但视觉噪音偏高

世界页是当前最复杂的页面。`ui_world.lua` 中子 Tab 包括地图、势力、报告；`ui_map_widget.lua` 实现了六边形网格、图层、国家边界、主权、资源、节点图标、HUD 控件。

截图中地图的优势是题材感强，但存在几个问题：

- 六边形底色、控制层、国家标签、图层按钮、节点图标同时出现，视觉噪音较高。
- 选中区域和可交互区域不够突出，玩家需要花时间判断哪里能点。
- 图层按钮很多，但多数早期锁定，灰色按钮在小屏上会形成“不可用噪音”。
- 地图固定高度 420，在当前手机截图里占据大量首屏高度，导致区域详情只能在下方阅读。

优化方向：

- 地图默认态应突出“可行动节点”，弱化不可交互背景国家。
- 锁定图层不要全部常驻展示，可改为一个“图层”按钮，展开后显示。
- 当前选中节点应有更明显的外描边、脉冲或底部标题联动。
- 地图详情卡应改为“摘要 + 展开详情”：首屏只显示控制度、治安、主导方、可行动按钮，人口、文化、模块路径等放二级。
- 可以考虑提供“战略视图 / 本地视图”切换。早期默认聚焦波黑，本地经营更重要；中后期再强调全欧洲。

### 3.4 武装页重要操作藏在下方，状态解释偏多

武装页顶部的总兵力、士气、战力、军费/季是合理的，但截图中“军事操作”在页面下方，玩家先看到多个说明卡片后才看到招募、裁军、补给。

问题：

- 招募、裁军、补给是高频操作，应比主管加成、工资、工厂维护更靠前。
- “编队管理”和“装备生产与管理”按钮样式相似，但它们的系统复杂度不同。
- 状态数据有解释，但缺少“问题诊断”。例如士气低、补给不足、军费过高时，应直接提示原因和解决动作。

优化方向：

- 将“军事操作”上移到主 KPI 卡之后。
- 把军务主管、工资、维护、补给储备收进“后勤详情”折叠卡。
- 主卡增加诊断文案，例如“补给可支撑 X 季”“士气将在 Y 季后跌入低迷”。
- 编队与装备建议以进度/状态表达：`0 编队 / 待编 5`、`兵工厂未建造` 已经有基础，可进一步加上“推荐：先编组护卫”。

### 3.5 市场页列表清楚，但投资决策信息不足

市场页股票标签目前展示商品价格、持仓、市值盈亏和股票列表。截图中的列表干净，但对于“是否买卖”缺少关键依据。

问题：

- 每只股票只显示价格和涨跌，缺少持仓数量、成本、估值偏离、风险标签。
- 商品价格和通胀在顶部出现，但与股票列表的关系不直观。
- 持仓为空时，只显示“暂无持仓”，没有引导玩家理解市场玩法。

优化方向：

- 股票行增加 1 个轻量信号：估值状态（低估/合理/高估）或近 4 季趋势。
- 持仓为空时给一个教学型空态：“可先少量买入矿业股，对冲金价波动”。
- 商品价格区可改为“市场指标条”，将金价、铜价、煤价、通胀分别作为可点击解释项。
- 交易弹窗中应强化“买入后现金、风险、预期收益”的后果预览。

### 3.6 图标体系混用 Emoji，风格不够统一

代码中大量使用 Emoji 作为图标，例如底部导航、快速行动、地图节点、状态提示、市场商品、武装标题等。优点是开发快、可读性强；缺点是在不同平台、字体和字号下风格差异明显。

问题：

- Emoji 色彩饱和度高，容易抢走旧金/羊皮纸主题的视觉中心。
- 不同 Emoji 的宽度和基线不一致，导致列表对齐不稳定。
- 当前 UI 想表达“账簿、工业、历史档案”，Emoji 会让部分界面显得偏轻。

优化方向：

- 短期保留 Emoji，但为核心导航和系统入口建立“单色图标规范”：底部导航、快速行动、资源栏优先替换。
- 资源类图标可逐步改为文本/符号化：`Au`、`Cu`、`C`、`AP`、`₿/克朗`，与地图资源层保持一致。
- 状态类图标只保留少数高识别符号：警告、战争、护盾、趋势。

### 3.7 文档与实现已有偏差，需要同步

`docs/ui-spec.md` 中仍描述快速操作为 6 个、3 列 × 2 行，但 `scripts/config.lua` 当前 `Config.QUICK_ACTIONS` 已变为 4 个，且人事/金融入口已移除到 Tab。

这类偏差会影响后续 UI 迭代：

- 设计文档不再完全可信。
- 新增页面时容易按旧规范实现。
- 视觉规范中的尺寸、布局与实际截图不一致。

优化方向：

- 将 `docs/ui-spec.md` 拆成“现行规范”和“历史方案”。
- 每次 UI 结构变化，同步更新页面结构、入口数量和设计原则。
- 本文档中的优化建议如果采纳，应反向沉淀到 `ui-spec.md`，避免变成一次性分析。

## 4. 全局分层组合方案

这一版建议不要走“大换皮”路线，而是基于现有 UI 做 **分层组合升级**。保留当前的深色账簿风格、顶栏、底部导航、卡片圆角、旧金强调色和现有组件体系，只调整模块之间的组织方式。

目标是让玩家在每个页面都形成相同阅读顺序：

1. 先看当前状态。
2. 再看本页最重要的问题。
3. 然后执行高频操作。
4. 最后查看详情、列表和解释。

### 4.1 页面统一四层结构

建议所有主要页面都按以下四层组织：

**第一层：页内状态层**

用于回答“这个系统现在怎么样”。通常放 3-4 个关键 KPI，不放复杂解释。

示例：

- Dashboard：AP、现金流、待处理事件、风险等级。
- 产业页：总产量、利用率、维护费、资源库存。
- 市场页：持仓市值、盈亏、负债率、通胀。
- 武装页：总兵力、士气、战力、补给可支撑季数。
- 世界页：总控制度、地区风险、势力威胁、可行动节点。
- 家族页：岗位空缺、成员数量、继承风险、培养进度。

**第二层：当前问题层**

用于回答“现在最需要注意什么”。这是每页的诊断区，可以是一条风险提示、一个待处理任务、一个推荐动作。

示例：

- “现金流为负，建议优先提升产出或减少支出。”
- “有 5 名护卫未编队，编组后战力会提升。”
- “萨拉热窝控制度仅 5%，可执行政治渗透。”
- “暂无持仓，可先小额买入矿业股熟悉市场。”

**第三层：行动层**

用于回答“我能做什么”。高频操作应该成组出现，并且每个操作显示结果和成本。

推荐格式：

`动作名 + 主要结果 + 成本`

例如：

- `招募工人 +5（75 克朗 / 1 AP）`
- `补充补给 +20（40 克朗 / 1 AP）`
- `政治渗透（控制 +10 / 2 AP + 30 影响力）`
- `买入股票（预计占用现金）`

**第四层：详情层**

用于回答“为什么会这样”。这里放列表、历史、数值拆解、说明文字和低频管理入口。详情层可以更紧凑，也可以通过折叠、子 Tab、弹窗承载。

### 4.2 模块组合类型

为了避免所有内容都是同一种卡片，建议建立几种固定模块类型：

**状态总览卡**

- 用于页面第一屏。
- 3-4 个 KPI 横向排列。
- 大数字 + 小标签，不塞长说明。
- 使用 `paper_dark` 或 `bg_surface`。

**诊断提示条**

- 用于风险、推荐、待处理事项。
- 高度较低，通常 1-2 行。
- 可以带一个右侧小按钮。
- 红色只用于真正风险，琥珀用于建议。

**行动组合卡**

- 用于高频操作。
- 按功能分组，不按系统随意堆叠。
- 每个按钮必须显示成本，关键按钮显示后果。
- 同一组按钮大小一致。

**焦点对象卡**

- 用于矿山、编队、股票、地区、家族成员等“当前选中对象”。
- 上半部分是对象身份，下半部分是 3-4 个关键指标。
- 只保留一个主按钮，其他操作进更多管理。

**详情列表区**

- 用于股票列表、贷款列表、编队列表、家族成员列表、地图节点详情。
- 不建议每一行都做厚重卡片。
- 使用紧凑行、细分隔线、右侧状态标签。

### 4.3 全局模块分工

各页面不需要视觉大改，但需要有明确分工。

**Dashboard：回合总控**

职责是把“本回合要不要处理事件、现金是否危险、AP 怎么花、能否结束回合”讲清楚。它不应该承载所有系统细节。

建议结构：

1. 本季状态总览：AP、现金流、事件、风险。
2. 当前问题：待处理事件或最严重经营风险。
3. 经营焦点：当前矿山/产业摘要。
4. 行动组合：推荐行动 + 全部快速行动。
5. 本季概览：资源、经济、民心、影响力。

**产业页：生产链**

职责是让玩家理解“资源从哪里来、产能卡在哪里、升级是否值得”。

建议结构：

1. 生产状态：金/铜/煤产量、利用率、维护费。
2. 生产瓶颈：工人不足、储量不足、控制度不足、维护过高。
3. 产业行动：招工、升级、探矿、迁移。
4. 矿山/工业区列表。

**市场页：资产账户**

职责是让玩家理解“资产、负债、风险、机会”。

建议结构：

1. 财务状态：总资产、总负债、现金流、通胀。
2. 市场提示：低估股票、债务风险、商品价格异常。
3. 市场行动：买卖、贷款、还款、商品处理。
4. 股票/贷款/商品列表。

**武装页：战备链**

职责是让玩家理解“战力来自哪里，下一步该补人、编队、装备还是补给”。

建议结构：

1. 战备状态：总兵力、士气、战力、补给季数。
2. 战备问题：未编队、补给不足、士气低、维护过高。
3. 军事行动：招募、裁军、补给、编队。
4. 装备与后勤详情。

**世界页：战略局势**

职责是让玩家理解“哪里能行动、谁控制、风险在哪”。

建议结构：

1. 战略状态：总控制度、治安、势力威胁、可行动节点。
2. 地图主视图：默认突出可行动节点，弱化锁定图层。
3. 选中节点摘要：主导方、控制度、治安、可执行行动。
4. 势力/报告详情。

**家族页：组织能力**

职责是让玩家理解“谁在岗位上、哪里空缺、培养谁、组织能力如何影响经营”。

建议结构：

1. 家族状态：成员数、岗位空缺、继承风险、培养进度。
2. 组织问题：关键岗位空缺、属性不匹配、成员老化。
3. 家族行动：任命、培养、招募/联姻等。
4. 成员列表和岗位详情。

### 4.4 广告/赞助组件的全局位置

广告组件不建议作为“资源图标”存在，也不建议成为每页主视觉。它更适合被定义为 **辅助行动层**。

推荐方案：

- 顶栏不再放老虎机图标。
- Dashboard 可以出现低干扰的“商会赞助”入口。
- 当现金不足、AP 不足、现金流为负时，赞助入口可以作为诊断提示条的次要按钮出现。
- 平时只在设置或更多操作里保留一个小入口。

视觉表达：

- 文案使用“商会赞助”“资金周转”“临时资助”，避免直接广告感。
- 样式使用小号描边按钮或信件式小卡，不使用高饱和图标。
- 不遮挡事件、结束回合和核心行动按钮。

这样广告保留商业化入口，但不会破坏经营模拟的沉浸感。

### 4.5 实施原则

这套方案的重点是 **组织方式变化，而不是视觉换代**。

保留：

- 顶栏 + 内容区 + 底部导航。
- 深色背景和羊皮纸卡片。
- 当前旧金色时代强调。
- 现有按钮、ProgressBar、Panel、Label 组件。
- Dashboard、家族、产业、市场、武装、世界的页面划分。

调整：

- 每页第一屏都先放状态总览。
- 风险/推荐从详情中抽出来，形成诊断提示条。
- 高频操作前置，低频详情后置。
- 列表更紧凑，减少重复厚卡。
- 广告从资源栏移到辅助行动层。

## 5. 分页面优化建议

### 5.1 顶栏 TopBar

优先级：高。

建议目标：让玩家 1 秒内看懂“我还能做几次行动、钱是否危险、当前年份阶段是什么”。

建议改造：

- Row1：主资源只保留现金、黄金、净资产/现金流二选一；产金和声望降级为小字或展开项。
- Row2：AP 变成主视觉，补充本季 AP 来源/惩罚提示。
- `+` AP 按钮显示剩余购买次数，例如 `+ 0/2` 或长按解释价格。
- 安全等级加入颜色语义和风险短语，例如“动荡不安：AP -1 风险”。
- 广告按钮从资源流中移出，避免影响经济信息阅读。

代码落点：

- `scripts/ui/ui_top_bar.lua`
- `scripts/config.lua` 的 `Config.SIZE.top_bar_height`、`ap_bar_height`
- `Config.FormatCompact` 与资源显示规则

### 5.2 Dashboard

优先级：高。

建议目标：把首页从“信息总览”改成“本回合行动驾驶舱”。

建议改造：

- 顶部增加“本回合建议”区域，只显示 1-2 条高优先级建议。
- 当前事件保持第一优先级，但如果没有待处理事件，应让经营风险或推荐行动顶上来。
- 焦点矿山改为紧凑卡，减少图片面积，优先展示产量、利用率、现金流影响。
- 快速行动从 2×2 改为“推荐操作横条 + 全部操作按钮”。
- 结束回合按钮可 sticky 到内容底部或在 Dashboard 中更早出现一次小型入口。

代码落点：

- `scripts/ui/ui_dashboard.lua`
- `Dashboard._BuildContent`
- `Dashboard._QuickActions`
- `Dashboard._SeasonOverview`

### 5.3 世界页与地图

优先级：高。

建议目标：把地图从“复杂系统展示”改成“可行动战略板”。

建议改造：

- 默认显示控制层 + 可行动节点，其他图层通过按钮展开。
- 锁定图层不要常驻占位，改为在图层面板中说明解锁条件。
- 选中节点详情首屏只保留 4 个字段：主导方、控制度、治安、可执行行动。
- 地图高度可根据屏幕动态计算，而不是固定 420。小屏上建议降到 300-340。
- 当前节点详情与地图选中态联动增强：标题、边框、地图描边使用同一 accent。

代码落点：

- `scripts/ui/ui_world.lua`
- `scripts/ui/ui_map_widget.lua`
- `MapWidget:_DrawLayerSelector`
- `MapWidget:Render`
- `WorldPage._CreateNodeDrawer`

### 5.4 武装页

优先级：中高。

建议目标：让玩家先处理战力、补给、士气，再查看后勤细节。

建议改造：

- 操作按钮上移到主 KPI 后。
- 主卡增加“战力状态诊断”：例如“未编队护卫较多，编组可提升战力”。
- 编队、装备、工厂三者建立更明确的流程视觉：招募 → 编队 → 装备 → 补给。
- 主管、工资、维护等放入“后勤详情”折叠区。
- 补给储备显示为可支撑季数，而不仅是单位数。

代码落点：

- `scripts/ui/ui_military.lua`
- `MilitaryPage._BuildContent`
- `MilitaryPage._BuildSquadCard`
- `MilitaryPage._BuildFactoryCard`

### 5.5 市场页

优先级：中。

建议目标：让市场从“价格列表”变成“投资决策页”。

建议改造：

- 股票行加入持仓数量或估值标签。
- 持仓卡展示“现金占用、总收益、最大风险提示”。
- 空持仓状态加入新手引导。
- 商品价格区与通胀区增加解释入口，说明它们如何影响矿业收入、军费和贷款。
- 交易弹窗加入交易后预览。

代码落点：

- `scripts/ui/ui_market.lua`
- `MarketPage._StocksTabContent`
- `MarketPage._StockRow`
- `MarketPage._ShowTradeModal`

## 6. 视觉规范优化

### 6.1 强化层级，不增加颜色

当前颜色已经足够多，不建议继续增加新色。更应该通过以下方式建立层级：

- 字号：核心数字使用 `data_large` / `data_mid`，说明使用 `label`。
- 背景：主操作卡使用 `paper_dark`，诊断/提示使用 `bg_surface`，次级详情用 `bg_inset`。
- 边框：只给当前选中、危险或主操作使用明显边框。
- 间距：高优先级模块之间留更大 gap，低优先级数据使用紧凑行。

### 6.2 建立状态语义

建议统一状态表达：

- 绿色：收益、稳定、可持续。
- 琥珀：注意、可执行但有代价、临界状态。
- 红色：危险、不可持续、阻塞行动。
- 蓝色：信息、科技、进行中。
- 金色：时代强调、主行动、高价值资源。

避免同一个颜色同时表示“选中、可点击、收益、标题装饰”等多种语义。

### 6.3 减少同质卡片

当前很多页面都是卡片堆叠。建议按内容类型区分：

- KPI：大数字 + 少量解释。
- 行动：按钮 + 成本 + 后果。
- 详情：左右 label/value 行。
- 列表：紧凑行，避免每行都像独立卡片。
- 警告：短句 + 推荐动作。

## 7. 交互优化

### 7.1 操作按钮统一展示“成本 + 后果”

当前按钮多显示成本，例如 `90 / 1AP`，但后果有时不够清楚。建议统一格式：

`动作名 + 结果 + 成本`

示例：

- `招募 +3（90 / 1AP）`
- `补给 +20（40 / 1AP，可支撑 +2季）`
- `渗透萨拉热窝（2AP + 30影响力，控制 +10）`

### 7.2 禁用态需要说明原因

现在禁用态主要依赖灰色、透明度或 Toast。建议按钮附近或长按弹出原因：

- 资金不足。
- AP 不足。
- 影响力不足。
- 尚未解锁。
- 已完全控制。

### 7.3 高频操作减少弹窗层级

科技、装备、交易等复杂系统适合弹窗；但简单操作如招募、补给、快速渗透可以尽量在当前页完成，并提供即时反馈。

## 8. 推荐实施路线

### P0：建立全局分层组合规则

- 为各页面统一引入“状态总览 / 当前问题 / 行动组合 / 详情列表”四层结构。
- 优先调整 Dashboard、武装页、市场页、世界页第一屏的信息顺序。
- 广告入口从顶栏资源组移出，改为 Dashboard 的辅助行动入口。
- 提炼可复用 UI 组合：状态总览卡、诊断提示条、行动组合卡、焦点对象卡、详情列表区。

预期收益：保留当前 UI 风格，但让所有页面的阅读顺序明显更清楚。

### P1：不改系统，只调整信息层级

- 顶栏瘦身，明确主资源与 AP。
- Dashboard 增加风险/建议摘要。
- 武装页操作上移。
- 世界页详情卡首屏压缩。
- 同步更新 `docs/ui-spec.md` 中已经过时的快速操作描述。

预期收益：最快改善首屏拥挤和决策路径。

### P2：地图与深度页体验优化

- 地图高度动态化。
- 图层入口折叠。
- 地图可交互节点高亮。
- 市场股票行增加持仓/估值信号。
- 按钮禁用原因标准化。

预期收益：提升复杂系统的可理解性。

### P3：图标与视觉资产统一

- 核心导航替换为单色图标。
- 资源符号统一为文本化/工业化符号。
- 快速行动图标统一风格。
- 逐步减少 Emoji 对主题氛围的干扰。

预期收益：提高完成度和商业化观感。

### P4：智能推荐与教学

- 根据 state 生成本回合推荐行动。
- 空态加入教学文案。
- 风险项直接提供解决入口。
- 新系统解锁时展示一次性引导。

预期收益：降低新手门槛，增强长期系统可玩性。

## 9. 可拆分任务清单

1. 建立状态总览卡组件规范：每页 3-4 个 KPI，统一大数字/小标签样式。
2. 建立诊断提示条组件规范：风险、推荐、待处理事项统一样式。
3. 建立行动组合卡规范：动作、结果、成本统一展示。
4. 顶栏资源重排：现金、黄金、AP 作为主信息，净资产/产金/声望降级。
5. 广告入口从顶栏移出，改为 Dashboard 的“商会赞助/资金周转”辅助入口。
6. Dashboard 新增“本回合状态 + 当前问题 + 推荐行动”的上半屏组合。
7. Dashboard 焦点矿山卡瘦身，降低图片高度。
8. 武装页把“军事操作”移动到主 KPI 卡下方。
9. 武装页补给显示“可支撑季数”。
10. 市场页增加财务状态总览和市场提示条。
11. 世界页节点详情改为摘要优先。
12. 世界地图图层栏折叠，隐藏未解锁图层。
13. 地图高度按屏幕高度动态计算。
14. 市场股票行增加持仓数量和估值/趋势提示。

16. 建立核心资源/导航的非 Emoji 图标方案。
17. 更新 `docs/ui-spec.md`，使其与当前代码一致。

## 10. 结论

当前 UI 的方向是对的：题材感明确、移动端结构合理、系统入口完整。下一阶段最重要的不是“做得更华丽”，而是 **把复杂系统翻译成更清晰的回合决策界面**。

优先建议从顶栏、Dashboard、世界页三个区域开始，因为它们决定玩家进入每回合时的第一感受：我有什么资源、现在有什么风险、下一步该做什么。只要这三个区域的层级变清楚，市场、武装、家族等深度页的复杂度就更容易被玩家接受。
